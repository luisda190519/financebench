# AppViabilidadNegocios — Benchmark System

This directory contains the complete infrastructure for evaluating LLM financial analysis
accuracy using the app as a ground-truth oracle.

## Quick Start

```bash
# 1. Generate 1000 synthetic business cases
npm run generate:dataset

# 2. Validate all generated cases pass structural checks
npm run benchmark:validate

# 3. (After LLM analysis) Batch-import LLM results
npm run benchmark:import-all -- --dir path/to/llm-outputs

# 4. Aggregate comparison results stored in MongoDB
npm run benchmark:aggregate

# 5. Export results to CSV for analysis
npm run benchmark:export-results
```

## How It Works

### 1. Ground-Truth Oracle

The app calculates financial metrics (NPV, IRR, payback period, EBITDA, cash flows) using
deterministic formulas verified against financial theory. These calculations serve as the
"correct" answer when evaluating LLMs.

### 2. Input-Only Cases

Each generated case contains only business inputs (no pre-calculated analysis). An LLM can
be given these inputs and asked to perform the financial analysis. The app then recalculates
the same metrics independently, enabling a direct comparison.

### 3. Comparison Engine

When a "Complete" JSON (with LLM-generated analysis) is imported, the app:
1. Recalculates all metrics from the inputs
2. Compares LLM values against app values field-by-field
3. Classifies each difference as: match (<1%), small (<5%), or large (≥5%)
4. Stores the comparison in MongoDB under `project.benchmarkComparison`

### 4. Aggregation

`aggregate.js` reads all stored comparisons and produces a research-grade summary with:
- Overall accuracy rate
- Accuracy broken down by metric (NPV, IRR, payback, etc.)
- Accuracy broken down by project type (10 categories)
- Accuracy broken down by scenario (optimista/normal/pesimista/controlado)

## Reproducibility

The dataset generator uses Mulberry32 seeded PRNG. Every case is deterministic:
- `caseIndex` seeds the RNG
- Re-running `generate:dataset` always produces identical output
